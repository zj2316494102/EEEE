# 本地开发、远程运行与结果同步方案

## 1. 方案目标

本项目采用本地开发、远程计算的工作模式：

1. 代码主要在本地 VS Code 中编写和维护；
2. 代码、配置和运行脚本同步到远程服务器；
3. 程序在远程服务器上运行，使用远程服务器的计算资源；
4. 远程运行产生的结果、日志和模型检查点按需同步回本地；
5. 本地代码与远程生成结果相互隔离，避免互相覆盖或误删除。

## 2. 最终采用的方案

采用“分流式双向同步”，而不是整个项目目录的双向镜像。

```text
本地代码、配置、脚本
          │
          │  单向上传
          ▼
远程 /home/user/EEEEEE
          │
          │  远程运行
          ▼
远程 runs、outputs、logs、checkpoints
          │
          │  单向下载
          ▼
本地 results
```

同步方向固定如下：

| 文件类型 | 同步方向 | 说明 |
|---|---|---|
| 源代码 | 本地 → 远程 | 本地是代码的唯一主版本 |
| 配置文件 | 本地 → 远程 | 不同步包含密钥的 `.env` 文件 |
| 运行脚本 | 本地 → 远程 | 远程使用同步后的脚本运行 |
| 运行日志 | 远程 → 本地 | 按需下载或任务完成后下载 |
| 实验结果 | 远程 → 本地 | 保存到本地 `results/` 目录 |
| 模型检查点 | 远程 → 本地 | 根据需要下载，避免占用本地空间 |
| 数据集 | 默认只保留在远程 | 不随每次代码同步重复传输 |

不建议使用整个项目目录的自动双向同步。代码和运行结果的修改来源不同，强制镜像容易导致代码覆盖、结果丢失或运行中的文件被删除。

## 3. 连接方式

服务器连接信息：

```text
主机：10.8.135.1
端口：51498
用户：root
远程项目目录：/home/user/EEEEEE
```

VS Code 使用已有的 Remote-SSH 插件连接服务器。建议使用 SSH 密钥认证，不在配置文件或同步脚本中保存密码。

### 3.1 生成本地 SSH 密钥

在 Windows PowerShell 中执行：

```powershell
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\eeeeee_ed25519"
```

首次连接服务器：

```powershell
ssh -p 51498 root@10.8.135.1
```

将公钥写入服务器：

```powershell
Get-Content "$env:USERPROFILE\.ssh\eeeeee_ed25519.pub" |
  ssh -p 51498 root@10.8.135.1 "umask 077; mkdir -p ~/.ssh; cat >> ~/.ssh/authorized_keys; chmod 600 ~/.ssh/authorized_keys"
```

### 3.2 SSH 配置

在本地文件 `C:\Users\zzz\.ssh\config` 中加入：

```sshconfig
Host eeeeee-remote
    HostName 10.8.135.1
    Port 51498
    User root
    IdentityFile C:\Users\zzz\.ssh\eeeeee_ed25519
    IdentitiesOnly yes
    ServerAliveInterval 60
    ServerAliveCountMax 3
```

配置完成后可以使用：

```powershell
ssh eeeeee-remote
```

当前密码仅用于首次配置。密钥认证正常后，应修改原有密码，并避免长期使用 root 运行应用。如果服务器存在普通用户，后续应优先使用普通用户运行项目。

## 4. 目录组织

本地项目目录：

```text
C:\Users\zzz\Desktop\E题\
├─ 代码、配置和脚本
├─ docs\
└─ results\              # 远程结果下载到这里
```

远程项目目录：

```text
/home/user/EEEEEE/
├─ 代码、配置和脚本
├─ runs/
│  └─ <run_id>/
│     ├─ outputs/
│     ├─ logs/
│     └─ checkpoints/
└─ data/                  # 远程数据集，默认不回传
```

每次运行使用独立的 `run_id`，例如：

```text
20260923_001
```

这样可以保留不同实验的结果，避免多次运行互相覆盖。

## 5. 代码上传

同步方案使用基于 SSH 的增量传输。Linux 或 WSL 环境可直接使用 `rsync`；当前 Windows 本机没有独立的 `rsync`，已配置 Rclone 1.75.1 通过 SFTP 实现同样的增量上传和下载能力。

本地已经配置以下脚本：

- `tools/sync_code_to_remote.ps1`：同步本地代码和文档到远程；
- `tools/pull_results_from_remote.ps1`：将远程运行结果下载到本地 `results/`。

VS Code 的 `.vscode/tasks.json` 已提供“同步代码到远程”和“下载远程运行结果”两个任务。

代码上传示例：

```bash
rsync -azP \
  --exclude '.git/' \
  --exclude '.venv/' \
  --exclude 'venv/' \
  --exclude '__pycache__/' \
  --exclude '*.pyc' \
  --exclude '.env' \
  --exclude 'data/' \
  --exclude 'results/' \
  --exclude 'runs/' \
  --exclude 'outputs/' \
  --exclude 'logs/' \
  --exclude 'checkpoints/' \
  -e "ssh -p 51498" \
  ./ root@10.8.135.1:/home/user/EEEEEE/
```

第一次同步应先进行模拟检查：

```bash
rsync -aznP \
  --exclude '.git/' \
  --exclude '.venv/' \
  --exclude 'data/' \
  --exclude 'results/' \
  --exclude 'runs/' \
  -e "ssh -p 51498" \
  ./ root@10.8.135.1:/home/user/EEEEEE/
```

确认文件列表正确后，再执行正式同步。默认不对整个远程目录使用 `--delete`，避免误删远程数据和历史结果。如果确实需要删除远程的旧代码，应只对明确的代码子目录使用 `--delete`，并先执行模拟检查。

## 6. 远程运行与结果目录

远程程序应将一次运行产生的所有文件写入独立目录：

```text
/home/user/EEEEEE/runs/<run_id>/
```

推荐的运行状态文件：

```text
RUNNING    # 程序启动时创建
DONE       # 所有结果完整写入后创建
FAILED     # 程序异常退出时创建
```

只有出现 `DONE` 后，才将该次运行的完整结果同步回本地。这样可以避免在文件仍处于写入状态时下载到不完整结果。

远程运行示例：

```bash
ssh eeeeee-remote "source /usr/local/iCompute/etc/profile.d/conda.sh && conda activate eeeeee && cd /home/user/EEEEEE && bash scripts/run.sh --run-id 20260923_001"
```

长时间任务应使用 `tmux`：

```bash
tmux new -s eeeeee
```

## 7. 远程 Conda 运行环境

服务器已有 Conda，无需另行安装 Miniconda 或 Miniforge。当前远程运行环境如下：

| 项目 | 配置 |
|---|---|
| 操作系统 | Ubuntu 20.04.6 LTS，x86_64 |
| Conda 根目录 | `/usr/local/iCompute` |
| Conda 版本 | 25.7.0 |
| 环境名称 | `eeeeee` |
| 环境路径 | `/usr/local/iCompute/envs/eeeeee` |
| Python | 3.10.21 |
| pip | 26.2.1 |
| GPU | NVIDIA GeForce RTX 3090，24 GB 显存 |
| NVIDIA 驱动 | 535.216.01 |

目前环境只安装了 Python、pip、setuptools 和 wheel 等基础组件。项目尚未提供 `requirements.txt` 或 `environment.yml`，因此暂不预装 PyTorch、CUDA 运行时或其他大型依赖，待代码依赖确定后再安装。

### 7.1 交互式终端中激活环境

通过 Remote-SSH 打开远程终端后执行：

```bash
conda activate eeeeee
cd /home/user/EEEEEE
```

### 7.2 非交互式 SSH 任务中激活环境

脚本或远程命令中应先加载 Conda，再激活环境：

```bash
source /usr/local/iCompute/etc/profile.d/conda.sh
conda activate eeeeee
```

完整运行示例：

```bash
ssh eeeeee-remote "source /usr/local/iCompute/etc/profile.d/conda.sh && conda activate eeeeee && cd /home/user/EEEEEE && bash scripts/run.sh --run-id 20260923_001"
```

后续如果项目根目录出现依赖文件，统一安装到该环境中：

```bash
conda activate eeeeee
cd /home/user/EEEEEE
pip install -r requirements.txt
```

不得使用系统 Python 或 Conda `base` 环境运行项目。

## 8. 结果下载

下载全部远程运行结果：

```bash
rsync -azP \
  -e "ssh -p 51498" \
  root@10.8.135.1:/home/user/EEEEEE/runs/ \
  ./results/
```

只下载某一次运行结果：

```bash
rsync -azP \
  -e "ssh -p 51498" \
  root@10.8.135.1:/home/user/EEEEEE/runs/20260923_001/ \
  ./results/20260923_001/
```

结果下载不使用 `--delete`，本地已有的历史结果不应因为远程目录变化而被删除。对于大型检查点，只有确实需要本地备份时才下载。

## 9. VS Code 日常工作流

建议同时使用两个 VS Code 窗口：

1. 本地窗口：打开 `C:\Users\zzz\Desktop\E题`，负责日常代码编辑；
2. Remote-SSH 窗口：连接 `eeeeee-remote`，负责远程终端、环境检查、程序运行和日志查看。

标准操作流程：

```text
本地修改代码
    ↓
同步代码到远程
    ↓
Remote-SSH 启动远程任务
    ↓
远程生成 runs/<run_id>/
    ↓
确认 DONE
    ↓
下载结果到本地 results/<run_id>/
```

后续可以在本地 VS Code 中配置三个任务：

- `同步代码到远程`；
- `启动远程任务`；
- `下载远程结果`。

## 10. 文件排除与安全规则

以下内容默认不参与代码上传：

- 本地虚拟环境，如 `.venv/`、`venv/`；
- Python 缓存和临时文件；
- 数据集和大型中间文件；
- 运行结果、日志和检查点；
- `.env`、SSH 私钥、API 密钥和其他敏感信息。

以下内容默认不自动删除：

- 远程 `runs/`；
- 远程 `outputs/`；
- 远程 `logs/`；
- 远程 `checkpoints/`；
- 本地 `results/`。

## 11. 方案结论

本项目最终采用：

```text
本地 VS Code
    + Remote-SSH 远程连接与运行
    + Rclone/SFTP（Windows）或 rsync（Linux/WSL）进行增量同步
    + /usr/local/iCompute/envs/eeeeee 作为统一运行环境
    + 独立 run_id 管理每次实验
    + 代码和结果分方向同步
```

该方案兼顾了本地开发便利性、远程计算性能、结果可追溯性和数据安全性。核心原则是：

> 代码只从本地同步到远程，结果只从远程同步回本地，不对同一批文件做无规则的双向覆盖。
