# 问题1 多模态情感特征提取与时序对齐方案

## 1 任务定位

问题1的核心是建立一套从附件1原始视频到标准化多模态时序特征的可复现流程，重点包括：

1. 文本、语音、视觉三种模态的特征定义与提取；
2. 不同采样频率和不同序列长度之间的时间对齐；
3. 样本编号、有效长度、填充规则和原始素材之间的可追溯关系；
4. 100条样本的完整结果汇总和典型样本验证。

附件2中的 `aligned_50.pkl` 和 `unaligned_50.pkl` 是问题2、问题3可以使用的标准化特征文件。问题1仍应从附件1的原始视频重新生成自己的特征文件。附件2可以作为字段组织、50个时间位置和维度设计的参考，不能直接作为问题1的自生成结果。

当前附件1包含37个 `video_id` 文件夹、100个视频文件和 `label-100.xlsx` 中的100条样本。现有文件可以通过 `video_id` 与 `clip_id` 一一匹配。

### 1.1 题目约束与接口边界

本方案需要同时满足题目要求和后续问题的数据接口，二者不能混写：

| 项目 | 问题1自生成结果 | 问题2、问题3训练与测试接口 |
|---|---|---|
| 数据来源 | 附件1的100条英文原始视频和标签表 | 附件2训练、验证数据，以及附件3、附件4专项测试集 |
| 文本特征 | `50×768` | `50×768` |
| 语音特征 | `50×768` | `50×74` |
| 视觉特征 | `50×768` | `50×35` |
| 主要用途 | 展示从原始视频重新提取和对齐的特征 | 训练鲁棒预测模型和可解释预测模型 |

因此，`768/768/768` 是问题1的自生成特征接口，不直接替换附件2的 `768/74/35` 接口。问题2和问题3的模型继续使用附件2规定的字段和维度；如果确实需要把问题1特征接入后续模型，必须单独建立适配层、保存适配参数并进行独立验证，不能在配置中直接把两套特征混用。

截至本方案核查，附件1的100条视频与100条标签记录可以完全匹配，附件2的实际字段和矩阵形状也与题目说明一致。问题1的设计已经具备题面适配性，但只有在完成全量运行、典型样本核验、提交包压缩检查和运行环境锁定后，才能宣称问题1结果完成。

## 2 总体流程

```text
label-100.xlsx + 原始视频
          ↓
样本索引与完整性检查
          ↓
音频提取、文本时间定位、视频帧解码
          ↓
文本、语音、视觉特征提取
          ↓
保留每个特征的真实时间戳
          ↓
统一划分为50个时间区间
          ↓
加权池化、标准化、缺失掩码和有效长度记录
          ↓
生成特征文件、清单、对齐日志和复现配置
```

建议区分“本地审计结果”和“最终提交结果”：

- 对齐结果：所有模态都转换为50个公共时间位置，作为问题1的全量特征文件和默认提交候选；
- 未对齐结果：保留各模态的原始序列、时间戳和有效长度，只作为本地审计、可视化和错误排查材料；
- 模型文件：只保存在本地或远程运行环境中，不放入竞赛提交包，提交包中记录模型名称、固定commit和下载方式。

## 3 样本索引与原始数据检查

### 3.1 唯一标识

每条样本使用如下字符串作为唯一标识：

```text
id = video_id + "$_$" + clip_id
```

该格式与附件2的 `id` 字段保持一致。例如：

```text
-3g5yACwYnA$_$13
```

### 3.2 `manifest.csv` 字段

建议为每条样本建立一行记录，至少包含以下字段：

| 字段 | 含义 |
|---|---|
| `id` | 样本唯一标识 |
| `video_id` | 原始视频标识 |
| `clip_id` | 视频片段标识 |
| `video_path` | 原始视频路径 |
| `duration` | 视频有效时长，单位为秒 |
| `raw_text` | 题目提供的英文转写文本 |
| `label` | 连续情感强度标签 |
| `annotation` | Negative、Neutral或Positive |
| `audio_sample_rate` | 音频采样率 |
| `video_fps` | 视频帧率 |
| `video_width`、`video_height` | 视频尺寸 |
| `text_length`、`audio_length`、`vision_length` | 对齐前各模态有效序列长度 |
| `feature_dim_text`、`feature_dim_audio`、`feature_dim_vision` | 问题1应为768、768、768 |
| `aligned_length`、`alignment_granularity` | 对齐后长度50及等比例时间区间规则 |
| `text_valid_ratio`、`audio_valid_ratio`、`vision_valid_ratio` | 50个公共位置上的有效比例 |
| `feature_status` | 特征提取状态 |
| `sha256` | 原始 MP4 校验值，正式运行时必填 |

### 3.3 完整性检查

程序运行前和运行后都应自动检查：

- 标签行数是否为100；
- 视频文件数是否为100；
- `video_id` 和 `clip_id` 是否一一匹配；
- 是否有重复ID、缺失视频或没有标签的视频；
- 视频是否可以正常解码；
- 音频和视频的有效时长是否基本一致；
- 所有输出特征是否存在NaN、正负无穷或错误维度。

标签应作为样本元数据保存。特征提取过程只使用原始多模态信息和题目提供的文本，不应使用情感标签生成特征，避免标签泄漏。

### 3.4 推荐的 Hugging Face 预训练模型

稳妥方案采用“一个主模型负责稳定的时序表示，情感分类模型只作为可选辅助特征”的策略。主模型全部冻结，不在100条附件1样本上微调。

| 用途 | Hugging Face模型 | 主输出 | 选择理由 |
|---|---|---|---|
| 文本上下文特征 | [`microsoft/deberta-v3-base`](https://huggingface.co/microsoft/deberta-v3-base) | 词级 `last_hidden_state`，768维 | 英文、上下文建模能力强，12层，隐藏维度768，适合短句和分词后特征提取 |
| 文本词级时间定位 | [`distil-whisper/distil-small.en`](https://huggingface.co/distil-whisper/distil-small.en) | 词级或片段级时间戳 | 英文专用，模型较小、速度快；只用于获得时间，不替换题目提供的文本 |
| 语音时序特征 | [`microsoft/wavlm-base-plus`](https://huggingface.co/microsoft/wavlm-base-plus) | 帧级隐藏向量，768维 | 直接接收16 kHz语音，适合提取语音内容、说话人和韵律相关表示，输出天然具有时间序列结构 |
| 面部情感特征 | [`dima806/facial_emotions_image_detection`](https://huggingface.co/dima806/facial_emotions_image_detection) | 面部 `CLS` 向量768维，7类情绪logits | 基于ViT，输入为224×224人脸图像，模型配置明确给出768维隐藏层和7类面部情绪输出 |

这组模型是稳妥方案的推荐组合。文本使用DeBERTa而不是基础BERT，语音使用WavLM而不是COVAREP作为主表示，视觉使用面部情绪ViT而不是只依赖手工AU特征。OpenCV或MediaPipe仍可用于人脸检测和跟踪，但面部情感编码器采用Hugging Face模型。

可以做两个辅助消融实验：

- 文本辅助特征使用 [`SamLowe/roberta-base-go_emotions`](https://huggingface.co/SamLowe/roberta-base-go_emotions) 的28维多标签情绪概率。该模型的训练文本来自Reddit，因此只作为辅助变量，不能替代DeBERTa主特征；
- 视频运动辅助特征使用 [`MCG-NJU/videomae-base`](https://huggingface.co/MCG-NJU/videomae-base)，输入16帧、224×224的视频片段，提取768维时空向量。该模型是Kinetics-400上的自监督视频表示，适合描述头部和身体运动，但不作为主面部情感模型。

语音情感专用模型 [`audeering/wav2vec2-large-robust-12-ft-emotion-msp-dim`](https://huggingface.co/audeering/wav2vec2-large-robust-12-ft-emotion-msp-dim) 可以输出唤醒度、支配度和效价三个连续属性，但模型较大，使用 `cc-by-nc-sa-4.0` 许可，并且在MSP-Podcast上微调。建议将其作为可选对照，不放入第一版主流程；如果使用，必须在论文中写明许可、训练域差异和推理窗口。

模型下载后应锁定具体commit或版本，并将模型卡链接、commit、权重文件校验值和实际 `transformers` 版本写入 `config.yaml`。这样即使模型仓库后续更新，也可以复现实验。

模型合规边界是“只使用已发布的预训练权重做特征提取”，不使用外部情感数据集对模型进行微调、阈值选择或参数优化。模型卡中的训练数据和许可信息要在论文中如实说明。

ModernBERT和WavLM的主输出是通用语义或语音表示，并不是经过本题标签监督训练的情感分类概率。为了使“情感特征”的含义更加完整，默认结果应保留视觉模型的7类情绪概率、语音韵律辅助变量和质量掩码；文本情绪概率、语音情绪概率和视频运动表示只作为单独的可选字段。主特征维度保持不变，不能把这些辅助字段未经说明地拼接到768维主矩阵中。

### 3.5 统一维度与高复现性方案（最终推荐）

根据“主特征尽量同维度、代码容易复现”的要求，建议把主流程固定为768维。文本、语音和视觉三种主特征都输出768维，可以直接拼接为2304维，也可以分别输入三个结构相同的融合分支。情绪分类结果和韵律统计量单独作为辅助字段，不改变主特征接口。

这里的768维接口是问题一针对附件一100条原始视频重新生成的特征接口，不追求复现附件二原有的74维语音和35维视觉特征。附件二只作为时间组织、字段命名和50个对齐位置的参考。问题1的结果独立保存为 `q1_aligned_50.pkl`；问题2和问题3继续读取附件2的 `audio` 74维、`vision` 35维输入。若后续把问题1特征接入使用附件2训练的模型，需要另行设计适配层、固定适配参数，并单独报告适配前后的结果。

| 用途 | 主流程模型 | 主输出 | 选择依据 |
|---|---|---|---|
| 文本主表示 | [`answerdotai/ModernBERT-base`](https://huggingface.co/answerdotai/ModernBERT-base) | 词级 `last_hidden_state`，768维 | 22层、149M参数、最长8192个位置，模型较新且与DeBERTa-base保持相同输出维度；模型卡给出标准Transformers用法 |
| 文本词级时间定位 | [`openai/whisper-large-v3-turbo`](https://huggingface.co/openai/whisper-large-v3-turbo) | `return_timestamps="word"` 产生词级时间戳 | 只负责时间定位，不进入主特征维度；标准Transformers接口，支持词级时间戳 |
| 语音帧级主表示 | [`microsoft/wavlm-base-plus`](https://huggingface.co/microsoft/wavlm-base-plus) | 帧级隐藏向量，768维 | `hidden_size` 和 `output_hidden_size` 都为768，约20 ms时间分辨率，使用标准 `AutoProcessor` 和 `AutoModel` |
| 视觉主表示 | [`dima806/facial_emotions_image_detection`](https://huggingface.co/dima806/facial_emotions_image_detection) | 面部 `CLS` 向量768维、7类情绪logits | 模型配置明确给出768维、224×224输入和7类标签，主流程不依赖动态提示词或远程自定义代码 |

这套方案在模型能力和工程稳定性之间取平衡：ModernBERT-base比原来的DeBERTa-base更新，同时保持768维；WavLM-base-plus具有稳定的逐帧语音表示；面部情绪ViT直接提供视觉表示和情绪分类输出。为了提高复现成功率，主流程不使用 `trust_remote_code=True`，不把SigLIP2或ExHuBERT放进默认结果文件。

可以做两个独立的能力消融，但不能改变主流程的输出契约：

- [`google/siglip2-base-patch16-224`](https://huggingface.co/google/siglip2-base-patch16-224) 可作为视觉嵌入消融。运行时必须断言输出维度为768，并记录实际 `transformers` 版本和读取字段；
- [`amiriparian/ExHuBERT`](https://huggingface.co/amiriparian/ExHuBERT) 可作为3秒窗口语音情绪消融。它需要 `trust_remote_code=True`，输出6维情绪概率，因此只保存到辅助字段，不进入768维主语音矩阵。

### 3.6 方案选择与复现边界

| 方案 | 主特征维度 | 主要模型 | 复现性 | 用途 |
|---|---|---|---|---|
| 统一768维主方案 | `768 / 768 / 768` | ModernBERT-base + WavLM-base-plus + 面部情绪ViT | 高 | 问题1默认提交和原始视频特征审计 |
| 能力消融方案 | 可能不等维 | ModernBERT-large、WavLM-large或SigLIP2 | 中 | 有额外GPU时用于比较，不改变主结果格式 |
| 原稳妥对照 | `768 / 768 / 768` | DeBERTa-base + WavLM-base-plus + 面部情绪ViT | 高 | 验证ModernBERT替换是否有效 |

最终建议使用统一768维主方案跑完100条样本，再用能力消融方案测试3至10条代表性样本。所有模型都冻结，不在这100条数据上微调；每个模型固定Hub commit、处理器、Transformers版本、PyTorch版本、随机种子和输入预处理参数。问题2和问题3的训练模型另行固定为附件2的 `768/74/35` 输入接口，不能因为问题1使用768维语音和视觉特征就修改附件2的原始字段定义。

## 4 文本模态特征

### 4.1 文本内容

直接使用 `label-100.xlsx` 的 `text` 列作为文本内容。建议同时保留两个版本：

- `raw_text`：原始文本，完全保留题目提供的内容；
- `normalized_text`：仅用于分词和时间对齐的副本，可以统一大小写、空格和标点。

不能用新的ASR结果替换题目提供的转写文本。ASR或强制对齐工具只用于获得时间信息。

### 4.2 文本向量

主方案使用冻结的 [`answerdotai/ModernBERT-base`](https://huggingface.co/answerdotai/ModernBERT-base) 提取词或子词级隐藏向量。为了提高不同Transformers版本下的可复现性，建议使用 `AutoModelForMaskedLM` 并设置 `output_hidden_states=True`，读取最后一个 `hidden_states[-1]`；如果当前版本的 `AutoModel` 已稳定支持ModernBERT，也可以读取其 `last_hidden_state`。该模型为英文编码器，22层，隐藏维度为768。原来的 [`microsoft/deberta-v3-base`](https://huggingface.co/microsoft/deberta-v3-base) 只作为对照模型。令 `D_text=768`，则每个词向量记为：

\[
e_{ij}^{text}\in\mathbb{R}^{768}
\]

其中 (i) 表示样本，(j) 表示第 (j) 个词或合并后的子词。

如果一个英文单词被拆成多个子词，可以对这些子词的隐藏向量取平均，得到一个词级向量。使用 `AutoTokenizer` 的快速tokenizer，并通过 `word_ids()` 将子词合并回单词。使用的tokenizer、模型名称、模型版本、最大文本长度和池化层应写入配置文件。

主文本特征维度固定为768。若需要显式的情绪变量，可以额外运行 [`SamLowe/roberta-base-go_emotions`](https://huggingface.co/SamLowe/roberta-base-go_emotions)，保存28维多标签情绪概率作为 `text_emotion_aux`。该辅助输出不与主文本向量直接混合，避免不同训练语域对主特征造成不可解释的影响。

### 4.3 文本时间定位

题目提供了文本内容，但没有直接提供逐词时间戳。建议采用以下方法：

1. 从视频中提取16 kHz单声道音频；
2. 主方案使用 [`openai/whisper-large-v3-turbo`](https://huggingface.co/openai/whisper-large-v3-turbo) 生成英文片段和词级时间戳；
3. 将对齐结果与题目提供的文本进行规范化匹配；
4. 对匹配失败的词保留原文本，并记录较低的对齐置信度；
5. 不要因为个别词对齐失败而删除整条样本。

主方案使用 `return_timestamps="word"` 获取词级时间戳。Whisper的感受野为30秒，若单条视频超过30秒，按30秒窗口切分并保留少量重叠，再将重复词合并。由于题目已经提供文本，ASR的输出只用于时间定位和置信度记录，不能替换原始转写文本。若显存不足，可以统一回退到 `distil-whisper/distil-small.en`，但必须修改配置并对全部100条样本使用同一个版本，不能在不同样本之间混用。

每个词保存：

```text
word, start_time, end_time, alignment_confidence
```

文本与Whisper词序的匹配必须使用固定规则，不能逐样本人工调整：

1. `raw_text` 永久保留原始文本；匹配副本统一使用Unicode兼容规范化、英文大小写统一、连续空格合并，并将弯引号、连字符和常见缩写写法映射为固定形式；
2. 对题目文本和Whisper结果使用同一套英文词级分词规则，删除只用于匹配的标点，但保留词在原文中的字符位置；
3. 先进行连续精确匹配，再用固定的编辑距离规则处理插入、漏词、重复词和缩写展开；匹配阈值必须写入配置文件，不能根据样本标签调节；
4. 一个题目词匹配到多个ASR子词时，取这些子词时间区间的并集；题目词未匹配时，优先使用相邻已匹配词的边界插值，无法插值时才在完整语音区间内按词序均匀分配；
5. 每个词记录 `match_type`、`alignment_confidence` 和是否使用了回退规则，低置信度词不能静默删除；
6. 文本编码不得静默截断。运行前统计token长度；长度超过设定上限时使用固定的溢出切片和合并规则，并在日志中记录切片数量。

如果整条样本的强制对齐完全失败，可以将文本视为覆盖整个语音片段，并按照词序在该区间内均匀分配时间，但必须将该样本标记为低置信度，并在全量汇总表中单独统计。

## 5 语音模态特征

### 5.1 音频预处理

从MP4文件中提取：

- 采样率：16 kHz；
- 声道：单声道；
- 数据类型：浮点型；
- 保留原始音频的起止时间，不截去视频前后的时间位置。

WavLM直接接收波形，不需要先将音频转换为MFCC或COVAREP。当前 `wavlm-base-plus` 配置中的卷积核和步长分别为：

```text
conv_kernel = [10, 3, 3, 3, 3, 2, 2]
conv_stride = [5, 2, 2, 2, 2, 2, 2]
```

有效步长和卷积感受野应由配置计算，而不是只使用一个固定的20 ms常数。令第 `l` 层的卷积核和步长分别为 `k_l`、`s_l`，则：

\[
S=\prod_l s_l=320,
\qquad
R=1+\sum_l (k_l-1)\prod_{j<l}s_j=400
\]

在当前卷积实现不对有效音频额外填充的条件下，第 `r` 个隐状态（`r=0,1,\ldots`）对应的采样区间近似为：

\[
I_{ir}^{audio}=\left[rS,\ rS+R\right),
\qquad
t_{ir}^{audio}=\frac{rS+(R-1)/2}{f_s}
\]

其中 `f_s=16000`。如果音频经过分块、首尾补零或处理器产生了 `attention_mask`，必须根据实际有效采样区间修正该时间段，并剔除补零造成的无效隐状态。实际运行时应读取当前模型配置的 `conv_kernel`、`conv_stride` 和处理器掩码，不能把 `320`、`400` 或中心偏移量写死在程序中。以实际有效区间为基准，可以构造：

\[
A_{ir}^{audio}=[s_{ir}^{audio},e_{ir}^{audio})
\]

### 5.2 特征定义

主方案使用 [`microsoft/wavlm-base-plus`](https://huggingface.co/microsoft/wavlm-base-plus) 的最后一层隐状态，配置中的 `hidden_size` 和 `output_hidden_size` 都为768。能力消融时可以换用WavLM-large，但不进入默认输出。令 `D_audio=768`，则第 (r) 个语音隐状态记为：

\[
x_{ir}^{audio}\in\mathbb{R}^{768}
\]

WavLM输出是通用语音表示，不直接输出情感类别。为了增强情感解释，可以额外提取5个低维韵律变量：基频、RMS能量、浊音概率、谱质心和过零率，并保存为 `audio_prosody_aux`。这些变量作为辅助特征，不改变主语音向量接口。

如果做语音情绪能力消融，可以增加 [`amiriparian/ExHuBERT`](https://huggingface.co/amiriparian/ExHuBERT) 分支。该模型期望16 kHz、3秒波形，建议使用长度3秒、步长1.5秒的滑动窗口。对第 (q) 个窗口定义时间区间 `B_{iq}^{emotion}=[u_{iq},v_{iq})`，保存6维概率向量：

```text
low_negative, low_neutral, low_positive,
high_negative, high_neutral, high_positive
```

ExHuBERT的6维输出先按照窗口的真实时间区间参与50段加权池化，再写入可选字段 `audio_emotion_probs`。视频首尾不足3秒的窗口采用零填充，同时记录 `audio_emotion_mask`。它需要 `trust_remote_code=True`，因此主流程不依赖它；默认结果只使用WavLM-base-plus的768维帧级表示和5个可复现的韵律辅助变量。

若需要与附件2的74维语音接口进行对比，可以将768维WavLM特征通过固定PCA压缩为74维，但PCA参数必须单独保存，而且论文中要同时报告原始768维和压缩74维的来源。主方案建议直接保留768维，避免在只有100条原始样本的情况下引入额外的降维不确定性。

对于无声帧或基频提取失败的帧：

- 保留其时间位置；
- 记录浊音或语音活动掩码；
- 对无效数值进行统一填充；
- 不能将无声帧直接当作普通的零向量输入而不保存掩码。

## 6 视觉模态特征

### 6.1 视频帧处理

主流程将视频重采样为25 fps以控制计算量，但必须同时保存原始视频的帧率、时间戳和输出帧率。若视频采用可变帧率或解码器提供帧级PTS，时间位置以实际PTS为准；只有在明确完成25 fps重采样后，才使用输出帧的中心时间：

\[
t_{ir}^{vision}=\frac{r+0.5}{fps_i}
\]

先使用固定版本的人脸检测和跟踪程序获得主要人脸框，再将人脸区域裁剪、扩展为正方形并缩放到224×224。默认跟踪置信度最高且持续时间最长的主要人脸。需要明确区分两个模型：`dima806/facial_emotions_image_detection` 只负责已经裁剪好的人脸的情绪分类，不负责检测和跟踪人脸；人脸检测器、跟踪器、模型文件或模型资产必须单独固定版本并记录SHA-256。

当前默认检测方案可以使用MediaPipe Face Detection，但在正式运行前必须补齐包版本、模型资产版本、检测阈值、跟踪规则、颜色空间、裁剪边界和失败处理规则。上述检测器信息没有写入配置并完成一次全量环境验证前，问题1不能宣称完全可复现。主方案使用 [`dima806/facial_emotions_image_detection`](https://huggingface.co/dima806/facial_emotions_image_detection)，其模型配置为ViT图像分类器，隐藏维度为768，输出7类面部情绪。SigLIP2只作为可选视觉能力消融，不进入默认流程。

如果输出帧不是25 fps重采样结果，则不能用帧序号除以25代替真实时间。所有视觉时间戳必须相对于当前MP4片段起点，裁剪到 `[0,T_i)`，并在未检测到人脸时保留该时间位置和无效掩码。

### 6.2 特征定义

主视觉特征使用面部情绪ViT的区域表示。代码加载 `AutoImageProcessor` 和 `AutoModelForImageClassification`，推理时设置 `output_hidden_states=True`，读取 `outputs.hidden_states[-1][:, 0, :]` 作为 `[CLS]` 向量，并读取分类头的 `logits`。第 (r) 帧保存两类输出：

1. 保存面部情绪ViT的最后一层 `[CLS]` 向量，作为768维视觉时序特征；
2. 保存面部情感ViT分类头的7维logits或softmax概率，作为面部情绪辅助特征。

记第 (r) 帧的视觉向量为：

\[
x_{ir}^{vision}\in\mathbb{R}^{768}
\]

7类辅助情绪的顺序固定为：

```text
sad, disgust, angry, neutral, fear, surprise, happy
```

人脸框坐标、检测置信度、`success`、人脸面积比例和相邻帧运动幅度单独保存为质量字段，不直接拼接到主视觉向量中。这样既保留了768维视觉表示，也能在对齐时使用质量权重。SigLIP2的图像嵌入可以作为额外消融，但必须单独记录模型commit、读取字段和实际输出维度。

如果需要研究短时动作和身体运动，可以把 [`MCG-NJU/videomae-base`](https://huggingface.co/MCG-NJU/videomae-base) 作为第二个视觉分支。该模型输入16帧、224×224的视频片段并输出768维时空表示，适合做运动特征消融，但会增加显存和计算量，不建议放入第一版主流程。

默认主视觉分支是“主要人脸的表情特征”，不等同于完整的身体动作特征。论文中应明确说明这一建模边界；如果典型样本存在遮挡、多人或明显身体动作，应在质量字段中记录，并把VideoMAE运动分支作为能力分析，而不能把人脸分类结果解释为完整视觉场景理解。

如果某一帧没有检测到人脸：

- 设置视觉有效掩码为0；
- 保留该帧的时间位置；
- 小范围缺失可以插值，但必须保存插值掩码；
- 长时间缺失不应被无条件补全。

## 7 跨模态时序对齐模型

### 7.1 公共时间网格

所有时间戳统一使用“当前MP4片段起点”为零点，单位为秒，区间采用左闭右开表示。音频、文本和视频的时间段都必须裁剪到 `[0,T_i)`；视频容器时间戳、音频提取偏移、分块重叠和补零区间需要在 `alignment_log.csv` 中记录。跨模态对齐使用片段内时间，不使用原始YouTube视频的全局时间。

设第 (i) 条视频的有效时长为 (T_i)，将其划分为 (K=50) 个等比例时间区间：

\[
B_{ik}=\left[
\frac{(k-1)T_i}{K},
\frac{kT_i}{K}
\right),
\qquad k=1,\ldots,K
\]

选择50个位置有三个原因：

1. 与附件2的 `aligned_50` 接口保持一致；
2. 不同视频时长可以转换到相同的序列长度；
3. 相比直接使用原始帧序列，存储量和后续模型复杂度更低。

这里的50个位置是时间重采样结果，不是简单截取每个模态的前50帧。

### 7.2 时间重叠权重

对于模态 (m) 的第 (r) 个原始特征，其时间区间为：

\[
A_{ir}^{(m)}=[s_{ir}^{(m)},e_{ir}^{(m)})
\]

定义该特征对公共时间区间 (B_{ik}) 的贡献权重：

\[
w_{irk}^{(m)}
=c_{ir}^{(m)}
\frac{|A_{ir}^{(m)}\cap B_{ik}|}
{|A_{ir}^{(m)}|}
\]

其中：

- (c_{ir}^{(m)}) 是置信度或质量权重；
- (|A\cap B|) 表示两个时间区间的重叠长度；
- 如果原始观测是瞬时帧，可以用帧中心附近的半帧区间近似。

### 7.3 加权池化

第 (i) 个样本、模态 (m)、第 (k) 个时间位置的对齐特征为：

\[
H_{ik}^{(m)}
=
\frac{\sum_r w_{irk}^{(m)}x_{ir}^{(m)}}
{\sum_r w_{irk}^{(m)}+\varepsilon}
\]

文本词向量、语音帧向量和视觉帧向量统一使用该公式处理。这样三个模态的第 (k) 个向量对应视频中的同一个时间区间。

### 7.4 有效掩码与有效长度

定义模态有效掩码：

\[
M_{ik}^{(m)}=
\begin{cases}
1,&\sum_r w_{irk}^{(m)}>0\\
0,&\sum_r w_{irk}^{(m)}=0
\end{cases}
\]

同时记录：

\[
L_i^{(m)}=\sum_{k=1}^{K}M_{ik}^{(m)}
\]

其中 (L_i^{(m)}) 是该模态在50个公共时间位置上的有效位置数。对于文本模态，还应额外保存原始词数；对于语音和视觉模态，应保存原始帧数。

## 8 填充和缺失规则

### 8.1 对齐结果

对齐后固定为50个时间位置。对于没有有效观测的区间：

- 特征在标准化后填0；
- 掩码设为0；
- 有效长度不增加；
- 不把填充0当作有效情感信号。

### 8.2 未对齐结果

未对齐文件保留每个样本的实际长度：

```text
text_length[i]
audio_length[i]
vision_length[i]
```

如果为了批量计算需要补齐到统一长度，则只在有效序列末端补0，并保存对应的padding mask。不能用补齐后的下标代替原始时间戳。

## 9 特征标准化

对每个模态的每一维特征进行标准化：

\[
\tilde{x}_{d}=\frac{x_d-\mu_d}{\sigma_d+\varepsilon}
\]

其中 (mu_d) 和 (sigma_d) 应记录在 `normalization.json` 中。

问题1中可以基于100条样本的有效特征统计量进行无监督标准化。如果这些特征后续被用于有监督训练，则应只用训练集估计标准化参数，避免验证集信息泄漏。

## 11 自动化验证

建议编写 `validate_q1_outputs.py`，至少完成以下检查：

### 11.1 完整性检查

- 样本数为100；
- ID唯一且与标签表一致；
- `video_id`、`clip_id`、视频路径和标签表逐条匹配；
- 三种模态均有输出；
- 特征维度符合配置；
- 没有NaN或无穷值；
- 掩码只包含0和1；
- 每个失败样本都有失败原因，不能用空文件代替失败记录；
- 问题1输出检查 `768/768/768`，问题2和问题3输入检查附件2规定的 `768/74/35`，两套接口不能混用。

### 11.2 时间检查

- 每条视频的时间网格从0开始，到 (T_i) 结束；
- 时间区间单调递增；
- 不存在负时间或超过视频时长的时间戳；
- 每个原始特征至少能映射到一个公共时间区间；
- 对齐后的50个位置与原始素材时间范围一致；
- WavLM时间段由当前 `conv_kernel`、`conv_stride`、有效音频长度和处理器掩码计算；
- 视频时间戳优先使用实际PTS，25 fps只作为明确重采样后的输出频率；
- 对齐权重和有效掩码能解释每一个填充位置的来源。

### 11.3 统计检查

对每条样本记录：

- 原始视频时长；
- 文本词数和文本有效比例；
- 原始语音帧数和语音有效比例；
- 原始视觉帧数和人脸检测比例；
- 50个时间位置上的各模态有效比例；
- 插值帧数和低置信度特征数量；
- 文本匹配失败词数、回退分配词数和ASR窗口合并次数；
- 人脸检测成功率、跟踪切换次数、长时间人脸缺失区间和插值帧数。

这些统计量可以写入 `alignment_log.csv`，并用于论文中的全量结果汇总表。

### 11.4 提交与环境检查

- 最终提交包解压后和压缩后的大小都记录，压缩包不超过50 MB；
- 提交包不包含 `models/`、虚拟环境、缓存和未对齐审计文件；
- 四个主模型的本地路径、完整commit和SHA-256与 `models/model_manifest.json` 一致；
- `transformers`、PyTorch、视频解码器、音频处理工具、人脸检测器和跟踪器的实际版本均已写入配置；
- 在干净环境中按README重新运行，能够得到相同的目录结构、字段、维度和日志状态。

## 12 典型样本验证

至少选择1条样本进行人工和图形化验证。建议展示：

1. 原始英文文本及词级时间区间；
2. 音频波形、语音活动区间和声学特征覆盖范围；
3. 视频关键帧和人脸检测结果；
4. 50个公共时间区间；
5. 三种模态的有效掩码；
6. 一个或两个代表性特征随时间的变化曲线。

可以用如下表格组织典型样本：

| 时间区间 | 文本词片段 | 语音特征状态 | 视频帧范围 | 对齐状态 |
|---|---|---|---|---|
| \([t_0,t_1)\) | word1 | 有效 | frame 1--5 | 完整 |
| \([t_1,t_2)\) | word2 word3 | 有效 | frame 6--10 | 完整 |

## 15 实现伪代码

```python
manifest = build_manifest(label_file, video_root)
validate_manifest(manifest)
profile = "uniform_768_reproducible"

for sample in manifest:
    duration = get_duration(sample.video_path)

    audio = extract_audio(sample.video_path, sr=16000, mono=True)
    text = load_provided_text(sample.raw_text)
    words = whisper_word_timestamps(
        audio,
        model="openai/whisper-large-v3-turbo",
        language="en",
        task="transcribe",
        return_timestamps="word",
    )
    words = align_timestamps_to_provided_text(words, text)

    text_raw = extract_text_features(
        text,
        model="answerdotai/ModernBERT-base",
        method="masked_lm_hidden_states_last",
        pooling="word_mean",
    )
    audio_raw = extract_audio_features(
        audio,
        model="microsoft/wavlm-base-plus",
        sample_rate=16000,
    )
    audio_emotion_raw = None  # ExHuBERT只在可选消融中开启
    vision_raw = extract_visual_features(
        sample.video_path,
        model="dima806/facial_emotions_image_detection",
        face_crop_size=224,
        output_hidden_states=True,
    )

    grid = make_time_grid(duration, K=50)
    text_aligned = overlap_pool(text_raw, words, grid)
    audio_aligned = overlap_pool(audio_raw.hidden_states, audio_raw.spans, grid)
    vision_aligned = overlap_pool(vision_raw.main_features, vision_raw.spans, grid)
    audio_emotion_aligned = (
        overlap_pool(audio_emotion_raw.probs, audio_emotion_raw.spans, grid)
        if audio_emotion_raw is not None else None
    )

    save_sample_result(
        sample_id=sample.id,
        text=text_aligned,
        audio=audio_aligned,
        vision=vision_aligned,
        auxiliary=collect_auxiliary_features(
            vision_raw.emotion_probs,
            audio_raw.prosody,
            audio_emotion_aligned,
        ),
        masks=collect_masks(),
        lengths=collect_lengths(),
        duration=duration,
    )

validate_q1_outputs()
write_alignment_log()
```
